# SentinelMail Known Issues & Drift

This document highlights the discrepancies between the expected architecture (as requested/prompted in past iterations) and the *actual* implemented codebase.

## 1. Missing Backend & Database (Critical)
**Expectation**: An Express backend running on port 3001 with a PostgreSQL database, migrations (`server/db/migrate.ts`), and `pg` pooling.
**Reality**: 
- The `server/` directory is entirely absent from the file system.
- The `postgres` and `express` dependencies in `package.json` are completely unused.
- The application relies on `src/lib/local-api.server.ts` running inside the Nitro SSR process.
- **Impact**: Any data created (analyzed cases, new vendors, analyst decisions) is ephemeral and lost when the container sleeps or restarts.

## 2. Missing LLM / AI Integration
**Expectation**: OpenAI integration for deep forensic analysis of email bodies, reasoning extraction, and intent classification.
**Reality**:
- The `openai` package is installed but unused.
- The EML parser (`src/lib/eml-analysis.server.ts`) relies on hardcoded string matches (`subject.includes("invoice")`) to generate mock evidence and risk scores.
- **Impact**: True generative AI analysis is not occurring. Threat detection is purely heuristic and mocked.

## 3. PDF Report Generation
**Expectation**: A `/api/cases/:id/report` endpoint returning a true binary PDF generated by `pdfkit`.
**Reality**:
- `pdfkit` is installed but unused.
- Both the frontend `DEMO_MODE` fallback and the `local-api.server.ts` implementation generate and return a `text/plain` string formatted like an ASCII table.
- **Impact**: The UI initiates a Blob download, but the file is a `.txt` file, not a `.pdf`.

## 4. Campaign Aggregation
**Expectation**: A robust backend mechanism to cluster related cases into "Campaigns" based on shared indicators (domains, IPs, hashes).
**Reality**:
- The `GET /api/campaigns` endpoint in `local-api.server.ts` is stubbed out and always returns `[]`.
- The frontend only shows campaigns because of the 6-second timeout fallback to `demo-data.ts`.
- **Impact**: Real uploaded emails will never be grouped into campaigns.

## 5. Authentication
**Expectation**: Secure access control.
**Reality**:
- The frontend uses Firebase Auth (`src/lib/google-auth.ts`) to authenticate users, but the backend (`local-api.server.ts`) performs **zero token validation**. 
- Any client can interact with the API endpoints without passing an `Authorization` header.

## 6. Vite 6 / Render Deployment Hacks
**Expectation**: Standard Cloudflare/Render Nitro deployment.
**Reality**:
- The deployment is using the `node-server` preset instead of the default `cloudflare-module` due to Wrangler port conflicts on Render.
- `vite.config.ts` includes `allowedHosts: true` to bypass strict Host header blocks enforced by Vite 6+ for `.onrender.com` domains.
- A 6-second AbortController timeout was added to `api.ts` to prevent the UI from hanging for 60+ seconds while the Render free tier sleeps.
